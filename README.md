# oblivious-transfer-java

本地运行的不经意传输（Oblivious Transfer, OT）协议服务。协议双方在**单个进程内**
通过有界阻塞队列交互，不依赖外部网络或第三方服务。发送方持有多组消息对，
接收方按选择位取回且仅取回被选择的一条消息：发送方无法获知选择位，
接收方无法获知未被选择的消息。

## 功能

1. **1 选 2 基础 OT**：基于素阶群上的 Diffie–Hellman/DDH 构造，安全性依赖
   离散对数困难假设。消息为任意字节串，两条消息长度不必一致。非法参数在会话
   建立前直接拒绝。
2. **批量随机 OT 扩展（IKNP）**：以 `kappa` 组基础 OT 交换独立随机的
   PRG 种子对，用 HMAC-SHA-256 计数器模式 PRG 把 κ 组基础 OT 扩展到任意
   数量；扩展阶段只使用 SHA-256 / HMAC-SHA-256 / HKDF / AES-GCM 等对称
   原语。接收方选择位被发送方不可知的 PRG 流一次性掩码，选择隐私与逐次
   执行基础 OT 同强度（归约为 PRG 伪随机性与基础 OT 发送方隐私）。
3. **选择位批量提交与消息兑换分离**：接收方先提交完整选择向量，再按配置批大小
   分批或单条严格顺序兑换；越界、错位、重复、超批请求一律拒绝。
4. **多会话并发**：每会话独立通道、独立信封密钥与独立状态；共享的
   `SecureRandom`、线程池、会话注册表均并发安全；单个会话异常不影响其他会话。
5. **中止与故障处理**：任一方失败或主动中止都会通知对端，对端下一次收发即可
   检测到 `PEER_ABORTED` 并终止；中止/取消不通过错误消息泄漏选择位；
   128 位随机会话标识永不复用。
6. **消息完整性**：所有协议消息封装在统一信封中，携带会话标识、消息类型、
   单调序列号与 AES-128-GCM 密文。AAD 绑定 `sessionId || seq || type`，
   伪造、截断、重复、跨会话混用均被拒绝，并返回可区分的 `ErrorCode`。
7. **大批量分批推进与取消**：批大小可配置；扩展按批推进，PRG 支持按
   偏移寻址，单批工作内存 `O(kappa × 批大小)`，与总传输量无关；
   扩展过程可取消，取消后擦除全部 PRG 种子与临时矩阵，不留可观察中间状态。

## 协议流程

### 基础 OT（DH/DDH）

群 `G` 为 RFC 3526 2048 位 MODP 群的素阶子群（生成元 4，阶 `q=(p-1)/2`）。

1. 发送方随机指数 `a`，公布 `C=g^a`。
2. 接收方选择位 `b`，随机 `r`，发送 `Pk=g^r·C^b`。
3. 发送方计算 `K0=Pk^a`、`K1=(Pk·C^{-1})^a`，用各自经 HKDF 导出的
   AES-GCM 密钥加密 `m0`、`m1`。
4. 接收方由 `C^r` 恰好得到 `K_b`，只能解密 `m_b`。

- 选择位隐私：`Pk` 在 `b=0/1` 下都为群上一致分布（信息论安全）。
- 未选择消息机密性：依赖 DDH（离散对数）困难假设。

### 批量扩展（IKNP：PRG 种子 + 单 U 矩阵）

1. **基础阶段**：双方执行 `kappa` 组基础 OT（角色互换：扩展发送方扮演基础
   OT 接收方，选择向量为随机 `s∈{0,1}^κ`）。扩展接收方为每列 j 生成一对
   **独立随机** κ 位 PRG 种子 `(k0_j, k1_j)` 作为基础 OT 的两条消息；
   扩展发送方按 `s_j` 取回 `k_{s_j,j}`，对配对种子 `k_{1-s_j,j}` 一无所知
   （基础 OT 发送方隐私，DDH）。
2. **承诺**：接收方提交 `n` 与带盐承诺 `SHA-256(domain ‖ n ‖ salt ‖ choices)`
   （salt 为每会话 256 位随机数）。盐使承诺对发送方计算隐藏：全零/全一等
   结构化选择向量也无法被穷举验证。
3. **扩展阶段**（按批推进，批大小可配置）：对每列 j，接收方只发送**一个**
   矩阵列 `U_j = G(k0_j) ⊕ G(k1_j) ⊕ (r批 ⊗ 1_κ)`，其中 G 为可寻址
   HMAC-SHA-256 PRG（`block_i = HMAC(seed, domain ‖ counter)`，域含列号），
   只展开本批比特区间。发送方计算 `Q_j = G(k_{s_j,j}) ⊕ (s_j ? U_j : 0)`，
   于是 Q 第 i 行 = T0 第 i 行 ⊕ (r_i·s)。
4. **行密钥**：发送方输出 `(H(i,Q_i), H(i,Q_i⊕s))`；接收方无论 `r_i` 为何
   都持有 T0 第 i 行（跨列收集 `G(k0_j)` 第 i 行块第 j 位），按 `r_i`
   选择散列域，恰好恢复被选那一项。
5. **兑换**：发送方用行密钥经 HKDF 派生 AES-GCM 密钥加密消息对，
   接收方只能解出选择位指定的一条。

**选择隐私（对发送方）**：发送方视图中 `U_j` 被其不可知的 PRG 流
`G(k_{1-s_j,j})` 一次性掩码，故 `U` 与选择向量 `r` 统计独立；
承诺带盐不可穷举；兑换请求只含批次游标与长度。发送方凭基础阶段状态、
自身随机源与全部收到的协议消息无法还原任何选择位，安全强度归约为
PRG 伪随机性 + 基础 OT 发送方隐私，与逐次执行基础 OT 相同。

**发送方隐私（对接收方）**：接收方只持有 `k0` 列种子，行密钥
`H(i, T0_i⊕s)` 需要未知向量 `s`（基础 OT 接收方隐私保证 `s` 对扩展
接收方隐藏），故未选择消息在计算上不可获得。

## 安全假设

1. **DDH/离散对数**：基础 OT 的未选择消息机密性（接收方隐私之外的
   发送方隐私）与基础 OT 选择位隐藏（`Pk=g^r·C^b` 信息论均匀）。
2. **PRG 伪随机性**：HMAC-SHA-256 计数器模式扩展（`StreamingPrg`）的
   输出对不持有种子的一方伪随机——这是扩展阶段选择隐私的唯一新假设，
   与标准 IKNP 一致。
3. **随机谕言/相关鲁棒性**：行密钥散列 `H(i,·)`（HMAC+HKDF，域含
   行号、总数与分支）建模为相关鲁棒散列，保证不同行密钥互不可推。
4. **AES-GCM**：信封与消息加密的机密性/完整性。

## 随机数来源

全部随机性来自 JDK `new SecureRandom()`（`SymCrypto.secureRandom()` 单例，
内部线程安全）：在 macOS/Linux 上由内核熵播种（NativePRNG/DRBG）。
使用点包括：群指数、AES-GCM nonce、会话标识、PRG 种子对 `(k0_j,k1_j)`、
扩展选择向量 `s` 与承诺盐。每粒 PRG 种子 128/192/256 位（随
`securityBits`），种子对两两独立。

## 隐私适用边界

- **选择隐私**针对半诚实但好奇的发送方：覆盖其全部可达状态（基础阶段
  种子、随机源、入站协议消息），对全零/全一/随机选择向量、任意批次
  划分与任意消息内容成立；不覆盖发送方 deviate 协议（如伪造基础 OT
  消息）的恶意模型，恶意接收方的一致性检查（IKNP 的 sacrifice/切留）
  亦未启用。
- **发送方隐私**针对半诚实接收方：未选择消息在 DDH + 随机谕言假设下
  计算不可获得。
- 进程内通道默认可信；跨进程部署时信封的 AEAD 仍提供完整性与防重放，
  但端点身份认证需由部署层补充。

## 配置项（`OtConfig`）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `securityBits` | 128 | 基础 OT 数量/安全位，支持 128/192/256，须为 8 的倍数 |
| `batchSize` | 1024 | 单批扩展与兑换的最大消息条数 |
| `channelCapacity` | 256 | 进程内通道有界队列容量（背压） |
| `stepTimeout` | 30s | 单步收发等待超时，超时返回 `TIMEOUT` |

## 使用示例

```java
OtService service = new OtService(OtConfig.defaults().batchSize(256));

List<MessagePair> pairs = ...;          // n 条消息对，长度可不同
byte[] choices = ...;                   // n 个 0/1
OtService.BatchSession session = service.createBatchSession(source, choices);
session.receiver().start(n, choices);   // 提交选择向量并完成基础 OT

while (session.receiver().cursor() < n) {
    byte[][] messages = session.receiver().redeemNextBatch();
    // messages[i] 恰好是 choices[cursor+i] 指定的那条
}
```

## 错误判定（`ErrorCode` 节选）

- 参数/状态：`INVALID_PARAMETER`、`INVALID_STATE`、`OUT_OF_RANGE`、
  `INDEX_MISMATCH`、`ALREADY_REDEEMED`
- 消息安全：`MESSAGE_TAMPERED`、`MESSAGE_TRUNCATED`、`MESSAGE_REPLAY`、
  `CROSS_SESSION_MESSAGE`、`DECRYPTION_FAILED`
- 生命周期：`SESSION_NOT_FOUND`、`SESSION_CLOSED`、`SESSION_ABORTED`、
  `PEER_ABORTED`、`SESSION_ID_REUSE`、`CANCELLED`、`TIMEOUT`

### 本轮新增：发送方视角选择隐私验证（`SenderViewChoicePrivacyTest`）

- **泄漏比特均匀性**：对全零、全一、随机选择向量（单批与多批），
  统计发送方可计算的最强泄漏候选 `ℓ(i,j)=U_j⊕G(k_{s_j,j})` 的对角位，
  断言其为公平比特（8σ 二项界），行多数票预测器命中率与随机猜测一致。
- **旧攻击回归**：对发送方收到的矩阵执行修复前的双矩阵异或提取，
  断言输出恒为全零、与选择向量无关。
- **掩码结构恒等式**：逐行验证 `U⊕G(k0)⊕G(k1) == r⊗1_κ`，并断言发送方
  每列恰好只持有两粒种子之一——即掩码选择位的唯一未知量正是发送方
  缺失的种子（一次性密码本论证的可检验形式）。
- **线上抓包**：以真实通道与真实基础 OT 跑完整会话，记录发送方收到的
  全部信封并用其密钥解开：矩阵字节均匀、承诺带盐（相同选择向量两次
  运行承诺不同，且不等于可穷举的无盐哈希）、消息类型序列符合协议。
- **无关性**：发送方视图分布不随传入消息内容（两次会话入站消息序列与
  长度逐条一致）、批次边界（批大小 1/7/64/n 均通过均匀性）或重复运行
  （两次运行矩阵逐位一致率 ≈50%）出现可区分偏差。
